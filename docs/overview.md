# 项目原理与代码导读

本项目研究 Sony A7C II（ILCE-7CM2）的像素位移拍摄与机内合成。本文说明处理流程、源码位置、公开材料与限制，阅读时不需要此前的聊天或私人研究笔记。

## 两个独立环节

**解锁拍摄功能**：相机固件中包含菜单权限和参数支持判断。本项目记录指定固件中这些限制的位置，提供离线生成修改副本、检查和还原副本的 Python 工具。它不安装固件、不连接相机。具体字节修改、输入哈希与方法见 [解锁研究](unlock.md)。

**合成照片**：相机先拍好同组 16 张 RAW，原生模块再读取这些文件、重建像素、调色并编码成一张 JPEG。这部分是相机处理器执行的 AArch64 C 代码，Python 只负责离线构建和日志解析。执行 Python 检查或编译命令不会在相机上开始合成。

解锁软件限制不等于已经证明传感器机械移动、曝光同步和所有设置都正确。项目保留实机反馈及其局限，不能仅凭菜单出现就认定完整拍摄功能已经安全可用。

## 一张照片怎样生成

```text
同组 16 张 ARW
    → 按 256 行窗口读取，每次凑齐一组 4 帧
    → 按像素位移顺序交错重建 RGB16
    → 校验线性像素、调色，按 16 行生成 RGB8
    → libjpeg-turbo 顺序编码为 JPEG 压缩数据
    → 写卡、回填拍摄信息和两种预览图
    → Flush、完整读回、核对校验值
    → 发布最终照片
```

历史输入单帧尺寸为 7040×4688；有效区域为 7008×4672，交错重建后输出 14016×9344，约 1.31 亿像素。编码设置为 JPEG Q90、4:2:2。源照片、白平衡和校验值均固定，当前模块会拒绝不符合条件的输入。

四个线程共同处理：文件线程负责读卡和写卡；重建线程与辅助计算线程处理像素、校验和调色；JPEG 线程编码。三个 RAW 工作槽暂存四帧窗口，八个 RGB8 槽在调色与 JPEG 之间交接像素。槽是可重复使用的缓冲区，不代表八张 RAW 整图常驻内存。

阶段之间会重叠：文件线程读下一组时，计算线程可以处理上一组，JPEG 线程也可以编码已经生成的行。因此各线程累计耗时相加会超过整张照片的实际耗时。

## 术语

| 名称 | 在本项目中的意思 |
| --- | --- |
| ARW／RAW | 相机保存的原始传感器照片；当前实现只支持指定的无压缩 U16 布局 |
| 条带／窗口 | 每次处理的若干行像素；无需同时把 16 张整图装入内存 |
| RGB16／RGB8 | 每个颜色分量分别用 16 位／8 位表示的像素数据 |
| CRC | 数据校验值，用来检查本次输入输出是否与参考结果一致；它不替代固件身份核验或画质评估 |
| SHA-256 | 用于严格识别固件、静态库及构建产物的文件摘要 |
| EXIF | JPEG 中的拍摄信息；索尼私有数据的保留情况另见性能文档中的版本说明 |
| MPF 预览 | 嵌入的 1616×1080 回放预览；另有 160×120 小缩略图 |
| Flush | 要求文件服务提交待写数据；之后仍需完整读回核对 |
| 发布 | 校验通过后通过文件服务将临时输出变为最终照片；不表示上传网络 |
| AArch64 | 相机处理器使用的指令集，不能把该模块当作 Windows 程序运行 |
| Fsys | 相机固件内部文件服务，原生代码通过已核对地址和指令签名调用 |

## 可以独立验证什么

在仓库根目录使用 Python 运行：

```console
python -m unittest discover -s tests -v
python tools/audit_public.py
python tools/patch_unlock.py --help
python tools/build.py --help
```

这些命令可以检查补丁逻辑、源码发布边界和文档链接，不需要相机、固件或第三方设备工具。测试使用合成数据，不能证明真实相机启动安全。原始镜像的离线校验需要自行合法取得与清单完全匹配的文件。

完整交叉编译另需 Python 的 `pyelftools`、Zig 0.13.0 和严格指定的 AArch64 JPEG 静态库与头文件，步骤见 [构建与集成边界](build-and-run.md)。本仓库没有附带该静态库；仅有版本号相同的库也可能不通过固定哈希检查。

固件输入统一使用未修改的原版 2.01。构建时通过 `--firmware-root` 指定原版解包目录，先只读校验 7 个文件及 19 处文件服务签名；不接收已有其他修改的 App 或 CP。完整要求见 [固件基线说明](firmware.md)。

## 机内运行还需要什么

仓库没有提供设备连接、固件安装或模块加载实现。集成者还需实现设备和运行库核验、独占执行与任务回收，并提供历史 16 张 ARW 及私有曲线文件。即使成功构建 `.so`，也不能直接复制到存储卡上由相机自动执行。

当前输出目录固定为新的 `173MSDCF`，已存在时拒绝执行；尚未支持自动选择任意一组 16 张照片。131 MP 成片机内放大仍失败。后续 DISP 信息修复属于另一个版本，没有混入本次计时对应的算法实现。

**16.530 秒是已有修改的机身配置下的历史实测，包含合成、写卡、完整读回和发布。** 当前统一原版输入要求，并清理了外部接入和临时路径，已另外进行离线校验；尚未在原版机身重新测试。详细阶段耗时与对照见 [性能记录](performance.md)，风险和使用约定见 [notices.md](notices.md)。
