## 为什么能比 33.472 秒快

此前版本读取约 40 MB/s，但这不是 SD 卡本身的物理上限。相机文件服务的 `Fsys_Read` 最终进入 `mcmn_drv_default_readv`；目标内存地址或文件偏移不符合对齐要求时，该路径会先读入中转缓冲，再复制到目标，增加 CPU 和内存开销。

本机读卡路径调查中，同样 1.053 GB 的旧读法为 24.176613 s，用户态 CPU 14.68 s；采样中 memcpy 占比 96.336%。改用 **4096 字节对齐的目标地址**和**512 字节对齐的文件起点**后，独立读卡探针为 5.0264225 s、用户态 CPU 0.19 s。这是独立探针结果，不能替换上表整链中含竞争的 6.879940 s 读调用累计。

具体方法是：设原窗口文件起点为 `offset`，计算 `prefix=offset&511`，从 `offset-prefix` 读入对齐区。CRC／重建只消费原始逻辑窗口，跳过本数据布局中 0 或 256 字节的前缀。保留原始逻辑字节与 CRC，没有通过少读数据得到提速。
