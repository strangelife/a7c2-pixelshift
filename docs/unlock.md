# A7C II 像素位移拍摄：软件限制与离线修改方法

本文说明指定 Sony A7C II 2.01 固件中像素位移拍摄的软件限制，以及如何在电脑上生成严格匹配的修改副本。这里的 C2 指 A7C II（ILCE-7CM2），CR 指用于对照的 A7CR（ILCE-7CR）。“摇摇乐”是像素位移多重拍摄的俗称。

项目只提供离线修改工具，没有相机安装器。解除软件限制与合成照片是两个独立环节；合成模块不会安装解锁补丁。完整项目关系见 [代码导读](overview.md)。

## 先理解修改对象

`appFw.so` 是本次研究的相机应用程序镜像，文中简称 App。WBI 是启动时恢复运行状态的快照镜像；若只改 App 文件而继续恢复旧快照，改动可能没有进入实际运行状态。

“窗口”指清单规定的一段文件字节；“描述”指保存参数支持判断函数和取值范围的数据结构。VA 是程序加载后的虚拟地址，文件偏移是字节在镜像中的位置，两者不可混用。ELF 重定位的 addend 是加载器用于计算最终地址的加数，涉及函数指针时需与描述同步更新。

研究方法分三层：开放相关菜单权限、使参数支持描述接受合法取值、处理旧启动快照中的状态。下文给出具体范围和证据；它们不构成完整刷机流程。

## 研究结果与实机反馈

已发现可复现的软件限制：22 个菜单权限、3 个参数支持描述、3 个 ELF 重定位 addend，以及 WBI2 启动快照中的旧状态。用户曾反馈真实 C2 菜单可用并能拍摄，随后取得同组 16 张 ARW 并完成机内合成测试。

本页离线补丁针对原始固件镜像；后续合成实测使用的机身程序还包含其他修改，两者完整哈希不同。不能将合成成功当作本页原始镜像补丁的完整安装验收。RAW 标签、软件状态或一张成片本身，也不等于已经独立量测了全部传感器机械位移与曝光同步。

项目当前统一以 [未修改的原版 2.01](firmware.md) 为输入基线。指定原版目录中的 App 和 WBI 已核对，与下表原始哈希一致；原版 CP 及运行库也已单独记录。下表候选哈希用于核对工具输出，不是另一种允许的原版输入。

## 2. 菜单与参数支持

菜单权限涉及模式父项、OFF／4 张／16 张和两组间隔选项，共 22 处，将原值 `0000` 改为 `0100`。机型索引为 C2 16、CR 15，对应权限列分别 9、8；这是所研究固件快照的保存值。

C2 的三个原生参数描述指向“不支持”哨兵 `0x28bbb68`。支持判断看函数指针身份，因此该哨兵即使返回 1，也不能理解为支持。

| 参数 | 含义 | 描述 VA | 新上界／数量 |
| --- | --- | --- | --- |
| `0x5db` | OFF／4 张／16 张 | `0x56ccda0` | 2／3 |
| `0x8a8` | 4 张间隔 | `0x56d10d8` | 8／9 |
| `0x8a9` | 16 张间隔 | `0x56d10f0` | 8／9 |

三个描述改用 C2 已有叶函数 `0x2472344`：`cmp w0,w1; cset w0,ls; ret`。它执行无符号 `value <= upper_bound`，保留合法取值边界，拒绝负数和越界值。没有修改通用哨兵或 App 的 `.text`。

每个描述是 24 字节 `{function, argument, count}`，分别使用 `{0x2472344,2,3}`、`{0x2472344,8,9}`、`{0x2472344,8,9}`。

| 参数 | 描述的文件偏移 | RELATIVE addend 文件偏移 |
| --- | --- | --- |
| `0x5db` | `0x56bcda0` | `0x8bb590` |
| `0x8a8` | `0x56c10d8` | `0x8c2418` |
| `0x8a9` | `0x56c10f0` | `0x8c2430` |

重定位 addend 必须同步修改，否则加载器可能写回旧指针。合计 App 有 28 个修改窗口、46 个实际变化字节。

## 3. 两条启动加载路线

**快照同步路线**：App 和配套 WBI2 研究副本一起修改。本次快照中 App 基址为 `0x7f62cd6000`，使用 4 KiB 页、39 位地址空间；已核对 22 个菜单对象从虚拟地址到物理地址的映射。快照中的函数指针使用“保存的 App 基址＋相对 VA”。这里只对清单固定的 WBI 镜像负责，不能套用其他相机现场快照。

原生初始化为型号不支持的父项及其选项增加一份禁用贡献；快照路线仅移除这一份：

| token | 含义 | 原值 → 候选值 |
| --- | --- | --- |
| `0x28c` | 模式父项 | 2 → 1 |
| `0x2927` | OFF | 1 → 0 |
| `0x2928` | 4 张 | 2 → 1 |
| `0x2929` | 16 张 | 2 → 1 |
| `0x105f` | 拍摄启动功能 `0x4142` | 1 → 1，保持 |

OFF 派生标志相应 `01→00`，其余原生限制保留。不能把计数或标志全部清零。WBI 有 30 个修改窗口、42 个实际变化字节。

**App 冷加载路线**：另一条研究路线是在替换 App 并完整读回后，使旧启动快照失效，让应用重新初始化参数和菜单，再以只读探针核对。仓库没有提供这条路线的设备安装、快照失效或探针执行工具。不能只改磁盘而继续使用旧快照。若先替换运行时描述再调用刷新，撤销阶段可能已经看不到旧的“不支持”描述，造成旧禁用计数残留。

这两条是不同方案，不能把其中一条的现场反馈当作两条都通过。

## 4. 离线生成与恢复

```console
python tools/patch_unlock.py inspect --image app --input private/appFw.so
python tools/patch_unlock.py apply --image app --input private/appFw.so --output private/appFw.pixelshift.so
python tools/patch_unlock.py restore --image app --input private/appFw.pixelshift.so --output private/appFw.restored.so
python tools/patch_unlock.py apply --image wbi --input private/nflasha5.bin --output private/nflasha5.pixelshift.bin
```

请先自行准备 `private/` 目录和严格匹配的输入文件。`inspect` 只检查输入；`apply` 写入单独的候选副本；`restore` 把受支持的候选副本还原为原始文件内容。这里的恢复只针对电脑文件，不是相机救砖功能。

上述命令不连接相机、不重挂载、不安装固件。生成的是解密后的研究副本，不是完整官方升级包。私有输入文件由使用者自行合法取得，不在仓库中分发。任意一个完整哈希或窗口原值不符都应停止，不能删掉守卫强行应用。

## 5. 已知问题和后续工作

实机反馈曾出现：开启像素位移模式后，即使不拍照，关机再开机也会报错；预先设为电子快门没有消除问题。曾记录的规避方式是关机前设 OFF。程序中已经找到该模式的结束清理调用链，但这不足以解释全部启动问题，当前不能标记为已修复。

本页的三个参数和菜单修改解决的是软件门控。传感器机械到位、曝光同步、机身校准系数及原始照片中的位移信息，仍需与拍摄反馈和合成正确性分别验证。
