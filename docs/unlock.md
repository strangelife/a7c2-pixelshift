# C2 解锁摇摇乐：已有研究与具体方法

本文整理 2026-11-12 起的 C2／CR 对照研究、原生加载模块研究及后续用户反馈。它与 JPEG 合成源码共同组成项目，但解锁补丁不由合成模块自动安装。

## 研究结果与实机反馈

已发现可复现的软件限制：22 个菜单权限、3 个参数支持描述、3 个 ELF 重定位 addend，以及 WBI2 启动快照中的旧状态。用户曾反馈真实 C2 菜单可用并能拍摄，随后取得同组 16 张 ARW 并完成机内合成测试。

早期原始镜像候选、后续工具的安装路径以及带 FL／LUT 修改的实测机程序不是同一个哈希合同。现有反馈不足以把所有历史安装模块都标为实机通过；本项目保留这一区别。RAW 标签、软件状态或一张成片本身，也不等于已经独立量测了全部传感器机械位移与曝光同步。

| 配套 WBI 镜像 | 267171648 | `db3730c8dbb2de71cfb7a66c343ba8e752e0f374a3a4104196ceac1e9d1b08dc` | `30e694fdee97e101ef937c877c563e99adc25e6c8361b5e430df21f628173d8f` |

文件大小相同并不足够；工具同时校验完整 SHA-256、每个原值、窗口不重叠及最终完整哈希。原始输入不会被覆盖。全部窗口见 [补丁清单](../unlock/patches/c2-2.01.json)。

## 2. 菜单与参数支持

菜单权限涉及模式父项、OFF／4 张／16 张和两组间隔选项，共 22 处，将原值 `0000` 改为 `0100`。机型索引为 C2 16、CR 15，对应权限列分别 9、8；这是所研究固件快照的保存值。

C2 的三个原生参数描述指向“不支持”哨兵 `0x28bbb68`。支持判断看函数指针身份，因此该哨兵即使返回 1，也不能理解为支持。

| 参数 | 含义 | 描述 VA | 新上界／数量 |
| --- | --- | --- | --- |
| `0x5db` | OFF／4 张／16 张 | `0x56ccda0` | 2／3 |
| `0x8a8` | 4 张间隔 | `0x56d10d8` | 8／9 |
| `0x8a9` | 16 张间隔 | `0x56d10f0` | 8／9 |

三个描述改用 C2 已有叶函数 `0x2472344`：`cmp w0,w1; cset w0,ls; ret`。它执行无符号 `value <= upper_bound`，保留合法取值边界，拒绝负数和越界值。没有修改通用哨兵或 App 的 `.text`。

每个描述是 24 字节 `{function, argument, count}`，分别使用 `{0x2472344,2,3}`、`{0x2472344,8,9}`、`{0x2472344,8,9}`。

| 参数 | 描述的文件偏移 | RELATIVE addend 文件偏移 |
| --- | --- | --- |
| `0x5db` | `0x56bcda0` | `0x8bb590` |
| `0x8a8` | `0x56c10d8` | `0x8c2418` |
| `0x8a9` | `0x56c10f0` | `0x8c2430` |

重定位 addend 必须同步修改，否则加载器可能写回旧指针。合计 App 有 28 个修改窗口、46 个实际变化字节。

## 3. 两条启动加载路线

**快照同步路线（第八轮）**：App 和配套 WBI2 研究副本一起修改。页表研究已核对 C2 App 基址 `0x7f62cd6000`、4 KiB／39 位页表、22 个菜单对象的 VA→PA 映射。快照中的函数指针使用“保存的 App 基址＋相对 VA”。这里只对清单固定的 WBI 镜像负责，不能套用其他相机现场快照。

原生初始化为型号不支持的父项及其选项增加一份禁用贡献；快照路线仅移除这一份：

| token | 含义 | 原值 → 候选值 |
| --- | --- | --- |
| `0x28c` | 模式父项 | 2 → 1 |
| `0x2927` | OFF | 1 → 0 |
| `0x2928` | 4 张 | 2 → 1 |
| `0x2929` | 16 张 | 2 → 1 |
| `0x105f` | 拍摄启动功能 `0x4142` | 1 → 1，保持 |

OFF 派生标志相应 `01→00`，其余原生限制保留。不能把计数或标志全部清零。WBI 有 30 个修改窗口、42 个实际变化字节。

**App 冷加载路线（第十七轮）**：固定窗口安装 App、完整读回后，通过原有 WBI 失效流程使后续冷加载重算状态，再用只读探针核对。不能只改磁盘而继续使用旧快照。若先替换运行时描述再调用刷新，撤销阶段可能已经看不到旧的“不支持”描述，造成旧贡献残留。

这两条是不同方案，不能把其中一条的现场反馈当作两条都通过。

## 4. 离线生成与恢复

```console
python tools/patch_unlock.py inspect --image app --input private/appFw.so
python tools/patch_unlock.py apply --image app --input private/appFw.so --output private/appFw.pixelshift.so
python tools/patch_unlock.py restore --image app --input private/appFw.pixelshift.so --output private/appFw.restored.so
python tools/patch_unlock.py apply --image wbi --input private/nflasha5.bin --output private/nflasha5.pixelshift.bin
```

上述命令不连接相机、不重挂载、不安装固件。生成的是解密后的研究副本，不是完整官方升级包。私有输入文件由使用者自行取得，不在仓库中分发。

## 5. 既有原生模块加载协议

历史研究使用本地 A7C2Tools 的 Jiritsu 原生模块入口：暂存 `.so` → 逐字节读回 → 写 request → 写 `/tmp/jiritsu/libJit.so` 触发加载 → 解析 result → 清理本任务临时文件。

| 模块 | 请求格式／结果 |
| --- | --- |
| 安装器 | 16 字节 `<8sII>`：`A7INS001`，mode 0 校验／1 安装／2 恢复，reserved 0；`a7c2.install.request/result` |
| WBI | 同格式：`A7WBI001`，mode 0 检查／1 失效；`a7c2.wbi.request/result` |
| 只读探针 | 无请求；`a7c2.runtime.result`，`A7PXS001`，1856 字节 |

历史 WBI 模块要求 `image_mode="2\n"`、`image_dev="*wbi4\n"`；失效动作是既有 `image_drop=1`、`image_mode=0` 流程。该协议记录不是通用 shell 命令或自动安装说明；遇到状态不同不能跳过检查。

历史 App 安装器只操作 28 个固定窗口，完整输入／输出哈希守卫，软件错误逆向恢复，并恢复只读挂载。它没有直接写原始闪存，也不等于断电事务保证。该模块涉及外部工具实现，本仓库不重新许可或打包它。已有工具集成时应保留完整同机备份、固定窗口合同、整文件读回、冷加载及只读探针复核。

## 6. 已知问题和后续工作

用户曾报告：开启摇摇乐后不拍照，直接关机再开机，也会报错；预先设为电子快门没有消除问题。旧规避记录是关机前设 OFF。已有 C2 `40EF → TrinityShotEnd` 清理链证据，不能简单归因于“C2 没有清理函数”，但现有记录不能把启动问题标为已修复。

从 AP `5DB/8A8/8A9` 到 `40EE`、CP 参数、Trinity 网格、目标包、SIO 和 RAW `202F` 标签的链路已有研究。机械到位、曝光同步及机身系数仍应与软件门控、拍摄反馈和合成正确性分别验证。
