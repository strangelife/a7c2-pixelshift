# 未修改的原版 2.01 固件基线

本项目当前以 Sony A7C II（ILCE-7CM2）2.01 **未修改的解包文件**为唯一受支持的输入基线。不要求预先加入其他功能修改。原版文件清单为 [original-2.01.json](../profiles/original-2.01.json)，本次离线核对结果为 [original-firmware-verification.json](../evidence/original-firmware-verification.json)。固件文件本身不随仓库分发。

## 如何识别原版

不能仅看文件名、大小或相机菜单显示的版本号。校验工具会逐一比对 7 个文件的大小和完整 SHA-256，任何一个不符都拒绝通过。

| 文件 | 原版 SHA-256 |
| --- | --- |
| `appFw.so` | `2ea02f7ecbc5bb917316fe8ef4ce5ffd87eb66efaae78ba2ce11420552df539b` |
| `cpapp-b.bin` | `f5a477588698ef965748903b8959a39ce4f59ffd4aee4d4234ef1670f56a1428` |

其余运行库和 WBI 的完整摘要、大小及解包后的相对位置均在清单中。路径以包含 `firmware.tar_unpacked` 的目录为根；同名的其他启动环境运行库不替代清单指定位置。

```console
python -m pip install -r requirements-dev.txt
python tools/verify_firmware.py --root /path/to/original-2.01
```

工具只读打开这些文件，不复制或修改固件，也不访问 USB。除了完整文件哈希，它还将源码使用的 Fsys 读写函数、挂载查询及重命名函数签名映射回原版 ELF 的可执行段，逐字节比较。当前共检查 19 处签名，其中包含读写辅助头文件重复引用的函数。

## 解锁、构建分别使用什么

**解锁工具**：原版 App 和配套 WBI 作为 `apply` 的输入；生成单独的修改候选副本。候选文件与原版哈希不同是预期行为，不代表输入基线变成了修改版。`restore` 只把受支持的候选电脑文件还原为原版字节，不是相机固件恢复工具。

**合成构建**：`tools/build.py` 必须提供 `--firmware-root`，先核对全部原版文件和原生函数签名，再进行交叉编译。固件不被链接或打包到输出模块；构建清单记录本次所核对的原版哈希。

**机内集成**：仓库没有设备连接或加载器，离线校验也不能证明相机当前实际运行的是这些文件。集成者必须在机内执行前另行核对设备的 App、CP 和运行库版本及哈希；不得以“电脑目录通过校验”代替对相机的核验。原版软件限制是否允许拍摄像素位移照片，与处理一组已有 ARW 的合成算法是不同问题。

## 历史计时如何理解

16.530 秒来自已有修改的机身软件配置。此次原版校验表明合成模块使用的文件服务签名与原版相符，但**没有在原版机身上重新执行完整合成**，不能由此断言原版也能达到该速度，或解锁、加载与发布均已通过机内验收。

本次调整的是项目输入要求和离线构建检查，没有向相机写入原版，也没有恢复相机固件。历史记录保留其真实测试条件，详见 [性能记录](performance.md)。
